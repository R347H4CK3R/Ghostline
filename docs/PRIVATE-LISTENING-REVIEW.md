# Private listening review

Open the authenticated companion `/listening` page, linked from source review. It lists technically checked processor outputs for jobs currently in `needs-review`, with a reference/preview audio pair and explicit Matches, Doesn't Match, or Unsure selection. Names and notes are inserted as text; no decision is preselected. The page does not import the existing private master as new candidates.

A snapshot binds the complete processor result, validated voice pack (including conditioning transcript and manifest), and exact preview bytes. Reference and generated hashes, independent word evidence and PCM non-silence/clipping checks are validated again before serving or recording. Current job state and attempt must still match. Malformed or changed output is shown as a per-job diagnostic rather than silently approved. Preview bounds match the processor's 600-second maximum; reference pack limits remain unchanged.

Decisions append to `listening_reviews` in the existing queue SQLite database with a unique review ID, timestamp, reviewer, note and immutable snapshot/audio hashes. History survives refresh. The API does not update or delete prior decisions. This records a user's subjective listening judgment; it does not prove who clicked, infer authorization, pass native/device gates, promote a candidate, change active conditioning, complete a video or remove its source link. All three decisions preserve active voices and queue state. A future promotion flow must consume the exact accepted revision with the remaining checks and preserve the previous accepted revision.

All HTML, catalog, audio and mutations require the existing private endpoint authentication. Mutations additionally require the existing page CSRF nonce header. Audio URLs are strict allowlisted selections, with no redirects, arbitrary filesystem paths or public media hosting. Content is returned no-store. The catalog validates at most 200 current outputs and 200 history entries per snapshot. Catalog validation cost is linear in audio duration; unusually long previews remain a performance follow-up. There is no automatic refresh loop on this listening page.

Regression fixtures use the real queue/pack/publisher/HTTP/SQLite/filesystem pipeline with original synthetic PCM. Only synthesis and recognition are substituted. Browser checks play both fixture audio clips, submit an explicit Unsure decision and verify durable history after refresh. These are not new neural voices, live likeness decisions, physical-device tests or evidence of a completed update workflow.
