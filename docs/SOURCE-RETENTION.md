# Persistent source retention (1.0 development slice)

The prior extraction-time MP4 cleanup policy is superseded. Acquisition now requires an explicit persistent `retention_root`; omission fails before downloading. All four production callers (automatic candidates, reviewed preparation, source inspection and RVC dataset preparation) pass a persistent root. No production inference or data migration has been performed by this source patch.

The store preserves downloaded originals, partial failed downloads, extracted reference WAVs, analysis audio and interrupted generated staging directories. A source URL hashes to a private directory; each download attempt and each consumer use has its own directory. Private UTF-8 records bind source URL, source ID, actual SHA-256 and size, available request ID, stage state and safe error type. Failed or cancelled uses do not erase files. A verified original can be reused after process restart without another download; its bytes are rehashed and media is decoded again before use. Corrupt cache data is rejected and preserved, never replaced silently. RVC audit-rejected audio is moved to a retained rejection directory outside the runnable dataset rather than deleted.

A cross-process nonblocking lock serializes source-store writers and consumers. Admission checks a per-configured-root 8 GiB store budget, 4,096 entry ceiling (128 entries reserved for new work), at most 32 source attempts, maximum download bytes, available disk reserve and bounded segment counts. Existing per-media process deadlines/cancellation, waveform/word/training gates and source checks remain. Capacity exhaustion refuses work; it never evicts originals or voices. Separate generated-output roots also receive admission checks; this is not yet a single global desktop-library storage controller.

All source/use records say `cleanupEligible: false`. There is deliberately no deletion function or API to manufacture delivery acknowledgements. The current in-memory sync log and `file_sent` events do not prove the iPhone saved anything. Durable authenticated destination acknowledgements, the final desktop folder transaction, automatic cleanup settings and resumed transfer plumbing remain integration work. Until those gates exist, retained files remain retained indefinitely and storage exhaustion is reported.

Existing jobs whose source was deleted under the former policy cannot have their originals retroactively restored. Existing prepared specifications and voices are not rewritten. The first deployment must keep old workers paused until all acquisition callers use this retention-safe implementation. Native Windows/ACL and full authenticated phone sync verification remain required before an end-to-end claim.

The historical standalone `full_cast_video_worker.py` is now disabled before imports, model loading or filesystem writes. Its former unconditional deletion is incompatible with verified delivery; use the retained queue pipeline instead. No environment override bypasses this guard.
