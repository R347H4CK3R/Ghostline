# Pending links and actual laptop progress

The lightweight monitor now reads `video-queue.txt` into the same SQLite queue used by the app endpoint and reviewed-recipe processor. Each line is a YouTube URL or `optional name<TAB>URL`. Blank lines and `#` comments without tabs are ignored; tabs distinguish records, including names beginning with `#`. All lines are validated before adding any of them. URL variants normalize to one video ID. Existing nonempty names in the database, including app edits, take precedence over stale file labels.

On each poll, database jobs missing from the text file are appended with canonical links and names. Existing bytes/comments are retained; neither failure, generated previews nor needs-review clears a link. The mirror is limited to1MiB. If validation, decoding, size or a detected concurrent edit prevents synchronization, the error is shown alongside the real database jobs instead of hiding their progress. File removal alone does not cancel a database job.

The database is the durable authority. The monitor is the only cooperating text writer and holds its process singleton; the endpoint continues writing SQLite. Append/fsync and a reread detect some external edits, but cannot provide a transaction with arbitrary editors. Missing mirror records are repaired on a later poll from the retained database. No universal file-editor concurrency or power-loss guarantee is claimed. Completion-ledger cleanup remains deliberately unimplemented.

The self-refreshing progress screen displays actual queue stage, percentage, attempt out of four and saved failure reason. Submitted names and errors are HTML-escaped. It does not infer speaker identity, approve likeness, mark a job complete or load a neural model. Game pause is displayed while the processor independently enforces its existing game/stop/pause controls. The full automatic pipeline flag remains false: raw video links still need reviewed preparation, and phone feedback, promotion and master-folder sync remain unfinished.

Review found hash-prefixed labels repeatedly appended, a1001-record mirror rejected by its own parser and bad input hiding processing jobs. Actual SQLite/HTTP/temp-file regressions reproduced all three before their fixes. The byte bound replaces the inconsistent record bound; authoritative database progress remains visible even when text synchronization fails.
