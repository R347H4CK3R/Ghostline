# Private source inspection and activity previews

This stage suggests audio activity regions for explicit source review. It does not separate speakers, read on-screen names, identify characters, establish permission, verify likeness, train a model, or complete a queued video.

The authenticated `/review` page offers **Inspect source on laptop** after the reviewer enters a source-use basis and separately approves private local inspection. This saves an initial inspection request; HTTP handling does not download media or allocate a neural model. The existing single queue worker processes the request on an eligible poll, respecting its lifetime database lock, pause/stop files, gaming checks, lease fencing and cancellation. Inspection requests and proposals live beside `queue.db`, independent of the synthesis work directory.

The existing bounded downloader obtains accessible public video without cookies or authentication bypass. It retains its 30-minute, 256 MiB and 300-second default bounds. Analysis decodes at most 1,800.02 seconds and about 57.6 MB of 16 kHz mono PCM, then rejects overflow beyond 30 minutes even if downloader metadata understates duration. The inspector has a 600-second cancellation deadline, a 90-second decode deadline, 30-second clip deadlines and one FFmpeg decode thread. It suggests at most 32 regions, each 0.5–12 seconds, using 20 ms RMS activity frames, a 0.01 threshold, short gap merging and padding. Music, effects and mixed speakers may be included. Silence can produce zero suggestions.

Original video and analysis PCM are temporary and removed on success or failure. Hash-bound 24 kHz mono PCM16 preview clips remain private under `proposals/<video>/<revision>/`; an owned queue transaction fences the atomic index pointer. Unchanged requests reuse validated cached previews instead of downloading again. `/inspection?video=<id>` reports request/proposal status and queue failures; authenticated immutable preview URLs validate inventory, path and content hash. Requests use the existing custom CSRF header. The page allows same-origin audio only and inserts proposal text using DOM text content.

**Use proposed times** fills times and suggested stable IDs only. Names stay blank, label bases stay unselected, and final source approval stays unchecked. The reviewer must listen, remove unsuitable regions, review each speaker/label and explicitly approve final local processing. The saved recipe binds the inspected revision and source SHA-256. Preparation refuses a changed subsequent download before transcription or synthesis. Source bytes are downloaded again during preparation, so provider remuxing can require a new review; this stage does not silently recover or replace existing recipes.

**Stop inspection** writes a cancellation marker; it does not erase previews, source links, reviews, cached voices or active references. Repeating the identical approved request resumes it. Existing recipes, prepared specifications and active/terminal jobs cannot receive a new initial inspection record. A changed record is refused rather than silently replacing the original.

The browser and filesystem regressions use an original synthetic audiovisual fixture. Acquisition is substituted with that fixture; actual FFmpeg decoding, activity detection, clipping, owned-worker publication, HTTP transport and browser review remain exercised. Synthesis/ASR are excluded from inspection. This is not live YouTube acquisition proof, phone testing, character generation or likeness evidence. The worker and endpoint must both load this implementation before the deployed flow works; a source commit alone does not establish deployment.
