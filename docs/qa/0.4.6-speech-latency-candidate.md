## Change

A successful speech request without speed/pitch/volume effects can retain the already validated shared F5 model for a 60-second idle timeout. A new request cancels the old expiry timer using a generation token. Idle models release on background/inactivity or memory pressure. Active loading/generation defers release until request completion, preventing invalidation mid-inference. Conversion explicitly unloads; effects unload before rendering; errors/cancellation do not retain the model. References are validated and reopened per request. No persistent model-integrity bypass, stock profiles, voice-store migration or network inference was added.

The first request still has startup cost. Requests after expiry or release still reload. Applying speed/pitch/volume effects deliberately sacrifices retention to free memory before rendering. Only pause changes can retain the model because they do not require the effects engine.

Suggestions now explain the existing quiet daily review/build route for owner-account requests. Explicit browser review, GitHub sign-in and separate public submission remain required; nothing private is attached automatically. Existing enabled monitor was inspected, and owner suggestion #47 was read successfully. A previous scheduled attempt is recorded, but its result is unavailable; successful scheduled execution is not claimed. No duplicate monitor was created.

## Measured results

All measurements use the production adapter, pinned neutral synthetic reference, identical 32-step/seed-0 settings and denied network access on hosted Mac Metal. The three matched WAV pairs in each run are identical; the strict final run asserts zero PCM difference and checks a changed text on a warm engine against its cold baseline.

| Repeat pair | Reload seconds | Reuse seconds | Saved seconds | Reduction |
|---|---:|---:|---:|---:|
| initial 1 | 16.23 | 14.32 | 1.91 | 11.8% |
| initial 2 | 17.98 | 16.56 | 1.42 | 7.9% |
| cache 1 | 15.84 | 13.82 | 2.02 | 12.7% |
| cache 2 | 18.18 | 16.70 | 1.48 | 8.1% |
| strict 1 | 18.31 | 16.89 | 1.42 | 7.8% |
| strict 2 | 26.92 | 14.68 | 12.24 | 45.5% |

The median of these six repeat pairs is **1.69 seconds / 9.9%**. First-pair results in each process are excluded from this summary because first-use initialization confounds them; raw values remain in [the evidence JSON](0.4.6-latency-measurements.json). The 45.5% repeat-pair outlier is included, not hidden, but cannot be attributed wholly to caching given hosted-runner variability. This small ordered sample does not establish a general speedup or predict iPhone performance. Adapter load time omits lazy neural-weight setup that occurs inside generation; compare total request times.

Peak process RSS across these runs reached approximately 1.54 GB. That is a high-water mark, not an idle-memory measurement or an iPhone footprint. Retention keeps model memory alive between requests; physical-device pressure and thermal behavior remain unverified.
